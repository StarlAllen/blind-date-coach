# 学习闭环：记忆、归因、改进、更新

**本文件不覆盖**：偏好本身怎么改（`preference-and-standards.md`）、单次怎么打分（`scoring-and-veto.md`）。这里只管「跨案例怎么学」。

单次复盘回答「这个人要不要继续」；闭环回答的是**「我为什么总在同一个地方卡住」**。相亲是重复博弈，见满 5–8 个人才有模式可谈，样本不够时的「反思」多半是情绪。

闭环只有六步，少一步就会退化成反刍：

**记录 → 归因 → 假设 → 实验 → 验证 → 更新**

## 一、记录：每次 5 分钟，八个字段

用 `assets/learning-log.md`，一行一个人，只记事实。

| 字段 | 说明 |
|---|---|
| 代号 + 日期 | 不用真名，保护对方隐私，也保护自己 |
| 渠道 | 介绍人 / 平台 / 社群 / 同事 |
| 走到哪个节点 | P1–P12（见 `decision-tree.md`） |
| 结果 | 继续 / 我停 / 对方停 / 自然淡出 |
| 分数 | T1 或 T2 的加权总分 |
| 一句话印象 | 写**具体行为**，不写评价（「全程在讲自己的工作」而不是「自私」） |
| 否决 | 无 / V0 / V1-哪一条 |
| 这次学到什么 | 一句，必须是可执行的

**存储要求**：本地文件，不写真实姓名、电话、住址、工作单位；三个月后做一次匿名化清理。**记忆是为了改进，不是为了建档案库。**

## 二、归因：四种，别笼统归到「我不行」

结果不好时，人本能地归因到自己（我不够好）或对方（男的都不行）。这两种归因都不产生动作。拆成四类：

| 归因 | 典型症状 | 改哪里 |
|---|---|---|
| **标准问题** | 条件都对，就是没感觉；或总有某一项让你反复下头 | `preference-and-standards.md` 的三层清单 |
| **渠道问题** | 连续几个是同类型的不合适；介绍人总推同一类人 | `profile-and-channels.md` 的需求说明书 |
| **表达问题** | 对方误解你的意图；本人和资料/初见印象差距大 | `profile-and-channels.md` + `conversation-bank.md` |
| **判断问题** | 前期高分后期崩；红旗早就有但被忽略 | `scoring-and-veto.md` 的锚点与否决清单 |

**归因顺序**：先查渠道（最好改）→ 再查表达 → 再查标准 → 最后才轮到「我不够好」。绝大多数人跳过了前三步，直接自我攻击。

## 三、模式识别：5 次以上才下结论

- 样本 < 5：**只记录，不做结论**。三次失败不代表任何模式。
- 样本 ≥ 5：看「卡点是不是同一个节点」。

三种典型模式：

| 模式 | 表现 | 常见根因 |
|---|---|---|
| **第四次断崖** | 前三次都很好，第四次开始莫名烦躁 | 亲密推进带来的不适，或用「挑毛病」回避深入 |
| **单边消耗** | 总是你主动，对方一冷你就退，然后再找下一个 | 对低回应容忍度太低，或只敢选「不会拒绝你」的人 |
| **条件满意、感觉缺席** | 条件全中，见了三次还是不想再见 | 用条件清单替代了感受评估，标准与真实需求脱节 |

反例（把个案当模式）：被拒一次就改标准、遇到一个海王就认为「所有人都不可信」、一次冷场就认定「我不会聊天」。**个案给情绪，模式才给动作。**

## 四、改进：一次只改一个变量，做 30 天实验

改三件事等于没改，因为分不清哪个起了作用。

**实验卡四要素**：
1. **假设**（一句话，可证伪）：「我总在第三次之后失去兴趣，是因为我一直在用条件清单评估，没有给感受留空间。」
2. **动作**（具体到可执行）：「接下来 3 次见面，先问自己想不想再见第二次，再看条件。」
3. **指标**（可量化）：「3 次里至少 1 次我想主动约下一次。」
4. **期限**：30 天或 3 次见面，到期即复盘，不无限延长。

结果只有三种：假设成立（保留新做法）／不成立（换假设）／数据不够（再来一轮，但别超过两轮）。

## 五、验证：六个可量化的指标

每月看一次，**看趋势不看单月**：

| 指标 | 怎么算 | 健康信号 |
|---|---|---|
| 邀约接受率 | 接受的邀约 / 发出的邀约 | 稳定或上升 |
| 首见→二次转化率 | 见第二次的人数 / 首见人数 | 上升 |
| 到确定关系的中位次数 | 见几次才确定（含失败样本） | 下降或稳定 |
| 主动发起比 | 我主动 : 对方主动 | 接近 1:1 |
| 「见完很累」占比 | 累的次数 / 总次数 | 下降 |
| **预测命中率** | 预测与结果一致的比例 | 上升 |

指标不涨也可能是**分母变了**（见的人变多、标准变严），看比例不看绝对数。

### 预测命中率：唯一能提高「精准率」的机制

做法很简单，但九成的人不做：**见面前写在纸上，见完对照。**

```
【见面前】这次见面，我预测：想见第二次 / 不想 / 说不准。
        最可能踩的雷：___。
【见完后】实际：___。预测对了没有：对 / 错。错在哪：___。
```

为什么必须写下来：不写预测，你只会记住「我早就觉得他不行」这种事后聪明——大脑会自动把结果改写成一个你「一直都有」的判断。写下来，你才能区分「我真的看准了」和「我猜对了」。

预测命中率长期低于 50%，说明你的判断依据是错的（可能过于依赖第一印象，或过度看重某一项）。这不是坏消息，是你第一次知道该改哪里。

## 六、周期：三级复盘

| 频率 | 做什么 | 产出 |
|---|---|---|
| 每次见面后 24h | 记录 + 打分 | 一行日志 + 决策卡 |
| 每 5 次见面 | 归因 + 模式检查 | 一个假设 + 一张实验卡 |
| 每月 | 看六个指标 + 月度复盘 | 保留/调整策略 |
| 每季度 | 重写一页纸档案 | 更新标准与权重 |

**权重只在季度调整**——这是 `scoring-and-veto.md` 里「中途不许改权重」的唯一例外，因为改权重必须有数据支撑，而不是因为某个人。

## 七、复盘 ≠ 反刍

| | 复盘 | 反刍 |
|---|---|---|
| 产出 | 一条明天就能做的动作 | 一段情绪和自我评价 |
| 时长 | 15 分钟内 | 想多久都能想 |
| 问的问题 | 「下次改哪一个变量」 | 「我到底哪里不好」 |
| 检验 | 写完能说出「明天做 ___」 | 写完更累，说不出一件事 |

**判断标准**：写完这段，我明天要做的一件具体事是什么？说不出来，就还在反刍。

## 八、闭环的终点：更新，然后回到起点

```
记录（一行日志）
   ↓
归因（标准 / 渠道 / 表达 / 判断）
   ↓
模式（≥5 次样本才成立）
   ↓
假设 + 30 天实验（一次一个变量）
   ↓
验证（五个指标）
   ↓
更新：改标准 / 改资料 / 改话术 / 改渠道
   ↓
下一轮记录
```

不更新的闭环等于没闭环——记录了一堆，标准和动作一个没变，那只是给自己看的心灵日记。

其中「改标准」这一步最容易乱改：见过一个人就改，是情绪；见满五个再改，才是数据。具体方法见 `preference-and-standards.md`——把偏好当版本管理，v1 想象版 → v2 修正版 → v3 收敛版，每次改动写下触发事件。

## 九、什么时候该停

如果连续两轮实验都没有改善，而且每次复盘都在消耗情绪，先把相亲停一个月。**循环的前提是人还有能量**；把「脱单」变成自我考核，指标只会更差。
